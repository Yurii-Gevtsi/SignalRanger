# Grounder placed visual scope

Goal: the battle scene creates a visible `grounder` sprite at the simulation's deployment point and removes its keyed visual when `GrounderRemoved` fires. No new art, animation, health bar, or simulation behavior. Existing resource path: `UI/Weapons/grounder`. Public battle setup is expensive in EditMode because the scene owns a large composition root, so the narrowest stable seam is the scene's event handlers invoked with real Unity GameObjects and `GrounderDeployedEvent`; inspect actual SpriteRenderer and its sprite, position, and keyed cleanup. This mirrors existing visual tests for other weapons. Acceptance: one grounder deployment creates one visible sprite using the imported resource; removal deletes its tracking entry and schedules the GameObject for destruction. RED should be a missing handler/visual failure, not missing resource or compile failure. Do not weaken the visual assertions or alter mine lifecycle.
