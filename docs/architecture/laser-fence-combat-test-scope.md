# Тестовий контракт: лазерний бар'єр

Дата: 2026-09-22. Цей контракт покриває runtime механіку `laser_fence` за бойовою специфікацією.

## Ціль

Гравець може встановити корпуси бар'єра в бою. Два корпуси одного власника в межах 5,4 світової одиниці формують промінь. Контакт противника з променем завдає базової шкоди, вимикає лише цей промінь та завершує хід ураженої активної цілі. Власник і союзники безпечні.

## Межі

У межах: доступність зброї, падіння та реєстрація корпусів, виявлення контакту з відрізком променя, одноразова шкода, безпека команди й завершення ходу.

Поза межами: перенесення корпусів транспортером, руйнування пострілом, presentation-розмір 0,5 та побудова UI-лінії. Ці пункти вимагають окремих керованих сутностей і presentation-перевірки.

## Приймальні сценарії

| Сценарій | Публічний шов | Спостережуване твердження |
|---|---|---|
| Встановлення | `TryFire`, `Tick`, `LaserFenceNodeDeployed` | Вибрана зброя не заблокована; після двох пострілів існують два корпуси. |
| Ворожий контакт | Переміщення стану/`Tick`, `BattleUnitState.Health`, `BattleState.Turn` | Противник на відрізку отримує рівно базову шкоду та його активний хід завершується. |
| Одноразовість | Наступний `Tick` | Той самий зв'язок не завдає шкоди повторно. |
| Командна безпека | `Tick`, HP власника/союзника | Дрони команди власника не отримують шкоди від свого променя. |

Тести використовують лише реальний `BattleSimulation`, її події та стан бою. Вони не викликають приватні helper-и й не перевіряють кількість внутрішніх викликів.

## Достатність

Чотири перевірки відтворюють весь описаний бойовий цикл: вибір → встановлення → контакт → шкода/хід → спожитий промінь. Вони не підміняють майбутню фізику перенесення й руйнування корпусів.
