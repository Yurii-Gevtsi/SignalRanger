# Тестовий контракт: бойовий промінь лазерного бар'єра

Дата: 2026-09-22. Контракт продовжує перевірену посадку корпусів і покриває решту runtime-механіки `laser_fence`.

## Ціль

Два корпуси одного власника, встановлені не далі ніж на 5,4 світової одиниці, формують промінь. Перетин ворогом завдає рівно базової шкоди, витрачає лише цей зв'язок і негайно завершує активний хід жертви. Власник і союзники не отримують шкоди.

## Межі

У межах: пошук пар корпусів, радіус 5,4, hit-test відрізка, шкода, споживання пари, безпека команди та перехід ходу.

Поза межами: presentation-лінія та масштаб корпусу, перенесення транспортером, руйнування корпусу пострілом, повторне з'єднання перенесених корпусів. Для них ще потрібні окремі керовані об'єкти та візуальна перевірка.

## Приймальні сценарії

| Сценарій | Публічний шов | Перевірка |
|---|---|---|
| Ворожий контакт | `TryFire`, `Tick`, `BattleUnitState.Health`, `TurnAdvanced` | Після двох реальних пострілів противник на лінії втрачає `weapon.Damage`; його хід передається іншій команді. |
| Одноразовість | Другий `Tick` | Те саме розташування не завдає повторної шкоди. |
| Безпека команди | Переміщення стану + `Tick` | Дроїд команди власника на тій самій лінії не втрачає HP. |
| Дальність | Реальні постріли + `Tick` | Пара на відстані понад 5,4 не б'є. |

## Тестовий шов

Тести створюють лише реальний `BattleSimulation` та використовують `TryFire`, `Tick`, публічний стан бою і подію ходу. Для відтворюваного розташування `BattleUnitState.MoveTo` синхронізується з `UnitMotor.Teleport`; приватні helper-и симуляції не викликаються.

## Достатність

Ці сценарії спостерігають повний бойовий результат, а не виклик внутрішньої функції: встановлення → промінь → контакт → шкода → витрачений зв'язок → переданий хід.
