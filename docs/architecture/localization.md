# Локалізація

## Джерело перекладів

Для кожної мови існує один UTF-8 JSON-словник у
`Assets/_Game/Content/Resources/Localization/`:

```text
uk.json
en.json
pl.json
de.json
es.json
fr.json
it.json
pt-BR.json
ja.json
ko.json
tr.json
ar.json
zh-Hans.json
```

JSON групує рядки за контекстом (`ui`, `intro`, `battle`, `content`), а
код звертається до стабільних ключів з крапкою: `ui.play`,
`intro.sigma.body`, `battle.ammo`.

Додати мову означає скопіювати `uk.json`, назвати файл кодом локалі
(`pl.json`, `de.json`) і перекласти тільки значення. Ключі не можна
видаляти або перейменовувати без зміни коду.

## Runtime

`JsonLocalizationService` завантажує словники через Resources, зберігає
вибраний код мови у `SaveSettingsData.languageCode` і використовує `uk`
як fallback, якщо переклад або мова ще відсутні.

Для параметризованих рядків використовуються іменовані маркери:

```json
"ammo": "Боєприпаси: {count}"
```

```csharp
AppServices.Localization.Translate("battle.ammo", new LocalizationArgument("count", 3));
```

## Безумовне правило для тексту гравця

**Усе, що гравець бачить, може побачити або прочитати на екрані, має
походити зі словника локалізації та мати непорожній переклад у кожній
наявній мові. Це правило не має винятків.** Воно стосується UI, навчання,
контенту, повідомлень про помилки, станів блокування, назв за замовчуванням
і текстів, які показуються лише в рідкісній гілці.

Заборонені буквальні player-facing рядки в C# та інших runtime-даних — у тому
числі fallback-рядки. Fallback не може бути українським, англійським чи іншою
мовою замість перекладу поточної локалі. Для ключа, який уже існує у всіх
словниках, у коді передається `string.Empty` або технічне безпечне значення;
реальний текст береться зі словника. Якщо ключа немає або переклад порожній,
це помилка локалізації, яку треба виправити до завершення зміни, а не обходити
fallback-текстом.

Технічні коментарі, імена ідентифікаторів, тестові очікування та службові
логи не є player-facing текстом і не додаються до словників, якщо вони не
можуть потрапити на екран гравця. Нефінальний контент також не є підставою
показувати текст іншою мовою: до фіналізації він має залишатися порожнім або
службовим станом, а після фіналізації — отримати ключі та переклади всіма
мовами.

Перевірка перед тим, як вважати роботу з гравцеським текстом завершеною:

- Кожен рядок, повернений методом, що формує UI-текст, походить із
  виклику `GameText.*` або `AppServices.Localization.Translate(...)`, а
  не з `return "..."`, `$"..."`, `switch { ... => "текст" }` напряму.
  `switch`/`if` можуть будувати **fallback**-значення, яке потім
  передається в `T(...)` — але сама фінальна повернена гравцю string
  завжди йде через виклик локалізації.
- Новий текстовий контент (нова зброя, нова механіка, новий екран) одразу
  отримує ключ і непорожнє значення в усіх 13 словниках. Додавання лише
  `uk.json` та `en.json` є незавершеною зміною.
- Перед комітом, що додає чи змінює гравцеський текст, зроби швидкий
  grep на рядкові літерали українською/англійською в змінених C#-файлах
  поза межами `GameText.cs`/`LocalizationRuntime.cs` — знайдений літерал
  означає пропущений випадок, а не виняток.
