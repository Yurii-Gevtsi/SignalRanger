# Переробка бойової фізики: єдина модель руху і єдина маска землі

Статус: реалізовано (2026-07-09), лишився ручний плейтест-тюнінг геймфілу.
Позначки: `[x]` виконано, `[ ]` заплановано.

## Проблема

Поточна реалізація бою нестабільна: юніти провалюються під текстури при
відкиданні від вибуху, зависають «головою» за піксель ландшафту, падають
в яму ривками. Корінь — не окремі баги, а модель:

1. **Немає єдиної фізичної моделі юніта.** Відкидання, стрибок і ходьба —
   три незалежні ad-hoc системи зі своїми таймерами, порогами і
   «лікувальними» механізмами (stuck-резолвери, hard timeouts,
   slide-кроки).
2. **Три уявлення про землю, які розходяться:** піксельна маска текстури
   (руйнація), heightmap-семплер «одна поверхня на колонку» (юніти),
   Physics2D-колайдери (снаряди, процедурні блоки, укриття). Cover-блоки
   не потрапляють у семплер; edge-колайдери будуються лише по верхній
   поверхні; heightmap принципово не представляє навіси й печери, які
   створюють кратери.
3. **Тунелінг за побудовою.** Приземлення визначається вузьким «вікном»
   пенетрації; на швидкостях падіння ~13 од/с юніт перестрибує вікно за
   один субстеп і летить до зони смерті.
4. **Фізика на variable `Update` dt** — фреймрейт-залежність і
   недетермінованість (блокер для майбутніх PvP/реплеїв).
5. **God-object:** усе бойове ядро в одному `BattleSceneController`
   (~3000 рядків) із приватними вкладеними класами.

## Принцип рішення (за референсом)

Референсний проєкт жанру доводить робочу схему:

- **Одна бітова маска землі** — єдине джерело правди про колізії для
  всього: юнітів, снарядів, руйнації, укриттів.
- **Одна модель руху юніта** зі станом `position, velocity, stable` і
  силами; вибух лише додає імпульс (`AddImpulse`) і знімає стабільність —
  далі та сама інтеграція обробляє політ, відскік, приземлення.
- **Інтеграція кроками по одній клітинці** (`steps = max(|dx|,|dy|)`),
  hit-test на кожному кроці — тунелінг неможливий за побудовою.
- **Crawl-механіка**: при м'якому контакті із землею юніт «виповзає»
  вгору до `crawlHeight`; ходьба — крок убік + підйом/спуск до
  `crawlHeight`, інакше падіння через ту саму фізику.
- **Відскок із затуханням** замість таймерів: `vx *= -0.3`, `vy *= -0.5`
  (коефіцієнти підбираємо під наш геймфіл).

## Цільова структура

```text
Assets/_Game/Runtime/Gameplay/Battle/
  Terrain/
    TerrainGrid.cs        // чиста C#: маска солідності, world<->cell,
                          // IsSolid, CarveCircle (dirty rect), StampRect,
                          // TryFindSurfaceBelow, Raycast
    BattleTerrain.cs      // фасад: grid + синхронізація runtime-текстури
                          // руйнівного шару (dirty-rect SetPixels32)
  Motion/
    UnitMotionProfile.cs  // розміри тіла, crawl-висота, швидкості,
                          // гравітація, коефіцієнти відскоку
    UnitMotor.cs          // чиста C#: Step(dt) з поклітинною інтеграцією,
                          // AddImpulse, Walk, StartJump, події
                          // Landed/StartedFalling/OutOfBounds
  Projectiles/
    ProjectileController.cs // інтеграція по масці замість Rigidbody2D
```

`TerrainGrid` і `UnitMotor` не залежать від UnityEngine-об'єктів сцени
(лише математика) — покриваються EditMode-тестами.

## Ключові контракти

### TerrainGrid

- Прямокутна сітка `bool[]` із `origin`, `cellSize`, `width`, `height`.
- Побудова: растеризація альфа-каналу руйнівного шару (поріг ~96) +
  штампи процедурних solid-блоків. Роздільність = піксель текстури; для
  чисто процедурних арен — фіксована (32 клітинки/од).
- `CarveCircle(center, radius)` повертає dirty rect; `BattleTerrain`
  оновлює лише цю область текстури (`SetPixels32(x,y,w,h)` + `Apply`).
  Оновлення 2026-10-09: `Apply` всієї текстури (арена ~3344×1882, ~25 МБ) щокадру давало ривки бурової ракети;
  тепер вирви за кадр збираються в один брудний прямокутник, який іде на GPU через малу проміжну текстуру й
  `Graphics.CopyTexture` (`BattleTerrain.FlushTextureUploads` з `LateUpdate`); без підтримки — повний `Apply`.
- Укриття (`DeployCover`) — `StampRect` у ту саму маску.
- Процедурні блоки нерушимі (як і зараз): кратер їх не вирізає.

### UnitMotor

Стан: `Position` (центр тіла), `Velocity`, `IsStable`.

- `Step(dt)`: `velocity += gravity*dt`; переміщення розбивається на
  кроки довжиною в одну клітинку; на кожному кроці hit-test тіла
  (перевіряються ведучі кромки «діаманта» тіла — ноги, голова, боки):
  - контакт знизу під час падіння → спроба crawl-up (підйом до
    `crawlHeight`); успіх = приземлення: швидкість 0, `stable = true`;
  - інакше відскік із затуханням по нормалі зіткнення;
  - вихід за нижню межу світу → подія `OutOfBounds` (смерть від падіння).
- `Walk(direction, dt)`: акумулятор енергії ходьби; на кожну клітинку —
  крок убік, при стіні wall-crawl вгору до `crawlHeight`, при обриві
  crawl-down до `crawlHeight`, інакше `stable = false` і юніт просто
  падає через `Step` (замість телепорту або миттєвої смерті).
- `StartJump(forward)`: перетворює дизайнові відстані/висоти стрибка
  архетипу на початкову швидкість (`vy = sqrt(2·g·H)`,
  `vx = D·g / (2·vy)`), далі політ і приземлення — звичайний `Step`.
  Стеля, стіни, ями обробляються автоматично.

### Снаряди

`ProjectileController` інтегрує рух сам (субкроки по клітинці),
hit-test: точка маски + перетин із юнітами (окрім власника). Гравітація
= `Physics2D.gravity * GravityScale` — траєкторії, прев'ю прицілу та AI
не змінюються. Rigidbody2D, CircleCollider2D і ребілд EdgeCollider2D
зникають.

### Симуляція

Фіксований крок симуляції (1/120 c) через акумулятор у контролері;
`BattleUnitState.Position` оновлюється щотік (стан — джерело правди,
view лише відображає). Це готує ґрунт для детермінізму
(PvP/реплеї) — залишиться замінити float-магію на фіксований тік мережі.

## Поза скоупом цього рефакторингу (наступні ітерації)

- Винесення бойового циклу з `BattleSceneController` у
  `BattleSimulation` (окремий крок декомпозиції god-object).
- Детермінізм для PvP (фіксована математика, реплеї).
- Вітер як іменована сила; гранати з відскоком (модель уже готова:
  bounce-коефіцієнти в профілі снаряда).
- Пул снарядів/ефектів, DI-контейнер, івент-шина.

## Ризики

- **Зміна геймфілу**: нова фізика приземлення/ходьби відчувається
  інакше. Мітигація: коефіцієнти в одному профілі, швидкий тюнінг.
- **Продуктивність растеризації** на великих аренах: будується один раз
  на завантаження арени; кратери — dirty rect. Прийнятно.
- **Процедурні арени без текстури** втрачають Physics2D-фолбек: маска
  будується з блоків, поведінка має збігтися (перевірити всі арени з
  `PrototypeArenaLibrary`).
