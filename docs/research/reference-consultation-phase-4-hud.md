# Reference Consultation: Phase 4 Battle HUD

Feature:
: Перший production mobile battle HUD замість IMGUI debug-панелі.

Example signals:
: У розпакованих прикладах battle-екрани мають окремі UI-атласи для HUD-елементів (кнопки дії, індикатори здоров'я, лічильники зброї/боєзапасу, індикатор сили). Помітно, що готові ігри тримають дію (постріл) і статус (здоров'я/хід) у протилежних зонах екрана, а кнопки дії — великі й у нижніх кутах під великий палець. Відгуки гравців окремо скаржаться на перевантажений UI зі зайвими банерами, лічильниками валют і промо-елементами прямо в бою.

Useful principles:
: Розділяти інформаційні зони (статус/здоров'я згори) і зони дії (постріл/скасування/зброя знизу). Кнопки дії — великі touch-таргети в кутах. Постріл — явне підтвердження окремою кнопкою, не по відпусканню пальця. Індикатор сили має бути видимим і читабельним під час прицілювання.

Risks to avoid:
: Не тягнути в бойовий HUD магазин, валюти, промо, банери й зайві лічильники. Не робити дрібні кнопки. Не покладатися на конкретне співвідношення сторін — заякорювати по кутах. Не копіювати чужі layout, іконки, атласи чи стиль.

Our original implementation:
: `BattleHudState` (snapshot) + `IBattleHud` (контракт) + `BattleHudView` (runtime uGUI). Статус/хід — top bar; per-team health bars — верхні кути; power meter — центр знизу; великі кнопки `FIRE` (справа), `Cancel`, `Weapon` (зліва), `Restart` — нижні кути. `CanvasScaler` ScaleWithScreenSize (ref 1080×1920, match 0.5) + кутове заякорення для стабільності на різних mobile-співвідношеннях. Постріл — окрема кнопка з явним disabled-станом. Жодних мета/економіка/промо елементів у бою.
