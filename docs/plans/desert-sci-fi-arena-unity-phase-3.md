# Phase 3 — складання пустельної sci-fi арени в Unity

## Результат фази

Готова до запуску бойова арена `arena.desert-sci-fi`, зібрана з восьми унікальних пар `visual + mask` та дев'яти незалежно руйнівних інстансів. Арена використовує чинну `BattleScene`, спільний анімований фон, наявні бойові персонажі, камеру, фізику пострілу й UI.

## Призначення в кампанії

- `arena.desert-sci-fi` є ареною Керіона (`chapter.basics`) і запускається для всіх його місій.
- `arena.training-meadow` не належить жодній кампанійній місії: її обирає тільки окремий режим «Тренування».
- Поки окрема арена Вальтари не створена, її поточні місії тимчасово використовують пустельну арену.

## Архітектурне рішення

- `ArenaDefinition` зберігає декларативний список модульних поверхонь.
- Кожна поверхня посилається на visual-спрайт, окрему collision mask, позицію та sorting order.
- Повторно використана мала платформа завантажує один source asset, але кожен інстанс отримує власні runtime visual і mask дані.
- `BattleTerrain` формує одну спільну collision grid як об'єднання всіх mask-поверхонь.
- Вибух очищає grid, visual і mask у кожній поверхні, якої торкається кратер.
- Старі арени без mask зберігають попередній alpha-based режим і процедурний fallback.
- Фон не входить до системи руйнування. Персонажі створюються чинним battle flow на spawn-точках арени.

## Автономна послідовність

1. Перевірити комплект visual/mask, layout та instances manifest.
2. Імпортувати в Unity тільки runtime-фрагменти; master-зображення не імпортувати.
3. Застосувати профілі імпорту: PPU 256, Full Rect, Bilinear для visual, Point і lossless/readable для mask.
4. Зареєструвати дев'ять інстансів у `ArenaDefinition` за координатами production-полотна 4096 × 2304.
5. Побудувати точну mask-driven collision grid без заповнення порожнеч під платформами.
6. Підключити спільний фон, camera bounds, spawn-точки й наявні character rigs.
7. Зареєструвати арену в каталозі та призначити її бойовому сценарію.
8. Запустити asset validation, EditMode tests і PlayMode smoke test.
9. Перевірити композицію, стики, landing, руйнування на межах кластерів і незалежність повторної платформи.
